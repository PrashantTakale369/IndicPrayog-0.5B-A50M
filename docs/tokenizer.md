# Tokenizer Documentation

This document centralizes tokenizer design, training, and evaluation details for **IndicPrayog-0.5B-A50M**.

## 1) Tokenizer Overview

The repository includes six 64K-vocabulary tokenizer variants trained for Hindi, English, and Marathi:

- **A**: BPE, mix_A (40/35/25), digit split enabled
- **B**: BPE, mix_B (33/33/34), digit split enabled
- **C**: BPE, mix_C (45/35/20), digit split enabled
- **D**: Unigram, mix_A (40/35/25), byte fallback enabled
- **E**: BPE, mix_A + UnicodeScripts pre-tokenizer step
- **F**: BPE, mix_A, digit split disabled

The final selected tokenizer is **Variant D (Unigram)**.

## 2) Architectures and Configurations

### Shared settings

- Vocabulary size: `64,000`
- Special tokens: `<pad>`, `<eos>`, `<bos>`, `<unk>`
- Unicode normalization: NFC

### BPE variants (A, B, C, E, F)

- Model: `tokenizers.models.BPE`
- Trainer: `BpeTrainer(min_frequency=2, initial_alphabet=ByteLevel.alphabet())`
- Pre-tokenization design includes:
  - custom split regex: ` ?[^\s\d]+| ?\d+|\s+`
  - optional per-digit split (`Digits(individual_digits=True)`)
  - ByteLevel with `add_prefix_space=False`, `use_regex=False`

### Unigram variant (D)

- Model: `tokenizers.models.Unigram`
- Trainer: `UnigramTrainer(byte_fallback=True)`
- Pre-tokenizer: `Metaspace`

## 3) Training Datasets

Tokenizer corpus is built by streaming data from:

- `ai4bharat/sangraha` (`verified` config) for Hindi (`hin`) and Marathi (`mar`)
- `HuggingFaceFW/fineweb-edu` (`sample-10BT`) for English (`train`)

Corpus mix for the main tokenizer setup (`mix_A`):

- Hindi: **600 MB** (40%)
- English: **525 MB** (35%)
- Marathi: **375 MB** (25%)
- Total: **~1.5 GB**

Other mixes used for ablation:

- `mix_B`: 33/33/34
- `mix_C`: 45/35/20

## 4) Training Methodology and Experiments

Pipeline scripts (in `IndicPrayog_tokenizer/scripts/`):

1. `01_sample_pools.py`: stream and build language pools
2. `02_build_variant_corpora.py`: build `mix_A`, `mix_B`, `mix_C`
3. `03_train_variants.py`: train variants A-F
4. `04_fetch_baselines.py`: fetch baseline tokenizers
5. `05_eval_all.py`: run intrinsic evaluation
6. `06_shortlist.py`: shortlist top candidates
7. `07_proxy_lm.py`: proxy-LM comparison for shortlisted variants

Key experimental design:

- Controlled ablation across six variants with matching vocab size and shared core setup
- Round-trip fidelity and Devanagari integrity used as hard quality gates
- Final selection validated via proxy-LM bits-per-byte (BPB)

## 5) Evaluation Methodology

Intrinsic evaluation computes:

- FLORES fertility (tokens/word) for `hi`, `mr`, `en`
- Parity ratios: hi/en and mr/en token count
- Round-trip fidelity
- Devanagari integrity (grapheme-preservation style metric)
- Held-out fertility and compression (bytes/token)
- Vocabulary utilization

Selection gate (`06_shortlist.py`):

- Keep only variants with:
  - round-trip fidelity >= 99.9%
  - Devanagari integrity >= Variant A
- Rank eligible variants by mean FLORES fertility; keep top-3 for proxy-LM

## 6) Evaluation Datasets

- **FLORES-200** (`haoranxu/FLORES-200`) for parallel-sentence intrinsic comparison
- **Held-out streaming docs** (2,000 docs/language) from:
  - `ai4bharat/sangraha` verified (`hin`, `mar`)
  - `HuggingFaceFW/fineweb-edu` sample-10BT (`train`)

For held-out extraction, the pipeline skips `300,000` streamed samples before collecting evaluation docs.

## 7) Results and Observations

From the consolidated experiment summary (`IndicPrayog_tokenizer/ex.md`):

- All custom variants achieve 100% round-trip fidelity
- Custom variants significantly improve Hindi/Marathi efficiency vs major English-centric tokenizers
- **Variant D (Unigram)** wins final proxy-LM evaluation (best mean BPB)
- Variant D is selected as the production tokenizer for IndicPrayog-0.5B
